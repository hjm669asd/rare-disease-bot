# 2.1 数据预处理：切分前先把数据整理干净

在 RAG 系统中，很多人一开始会直接讨论 chunk_size、chunk_overlap、语义切分等技术，但真正影响检索质量的第一步，往往是数据预处理。

一句话总结：**混乱的数据会切出混乱的 chunk，混乱的 chunk 会导致混乱的检索结果。**

## 为什么数据预处理重要

智能医疗机器人面对的知识来源可能包括：

- 医院 FAQ
- 科室宣教材料
- 药品说明书
- PDF 指南
- 网页文本
- 表格数据
- 医生整理的问答文档
- OCR 识别后的扫描件

这些数据经常存在问题：

- 标题层级混乱
- 段落边界不清晰
- 多个主题混在一段里
- 表格被 OCR 成乱序文本
- 页眉页脚、页码、版权说明混入正文
- 同一句话被重复多次
- 单位、数字、检查指标被拆散

如果不先整理这些问题，后续无论使用哪种切分策略，检索效果都会受到影响。

## 手动整理数据是允许的

在教学项目和真实企业项目中，都不要迷信“全自动处理”。

如果数据集很乱，可以先手动整理成更清晰的格式，例如：

```text
【疾病名称】高血压
【适用人群】成年人，高血压患者
【核心建议】
1. 定期监测血压。
2. 减少钠盐摄入。
3. 保持规律运动。
4. 遵医嘱服药。
【风险提示】
如出现胸闷、剧烈头痛、视物模糊等情况，应及时就医。
```

这种格式比一大段混乱文本更适合切分和检索。

## 推荐的数据预处理动作

### 1. 删除无关内容

删除页眉、页脚、页码、版权声明、导航栏、广告、重复免责声明等内容。

### 2. 明确标题层级

把内容整理成清晰结构：

```text
# 一级主题
## 二级主题
### 三级主题
```

标题本身会提供重要语义，能帮助后续切分和检索。

### 3. 一个段落只讲一个主题

不要把高血压、糖尿病、感冒、用药安全全部混在一段里。

更好的方式是：

```text
【高血压日常管理】
...

【糖尿病饮食与监测】
...
```

### 4. 保留关键上下文

医疗文本中，指标、条件、适用人群非常重要。

例如不要把下面内容切散：

```text
若发热超过三天、体温持续高于 39 摄氏度、出现呼吸困难，应尽快就医。
```

### 5. 统一术语

同一概念尽量使用统一说法：

- 高血压患者
- 血压升高人群
- 高血压病人

可以统一为“高血压患者”。

### 6. 给文档添加元数据

真实项目中，可以给每篇文档补充：

- 来源
- 科室
- 更新时间
- 适用人群
- 风险等级
- 文档类型

这些元数据后续可以用于过滤检索。

## 示例代码

下面的代码演示如何读取“混乱文本”和“结构化 Markdown 文本”，并对比它们在可读性和结构上的差异。

```python
from pathlib import Path


BASE_DIR = Path(__file__).resolve().parent.parent
MESSY_DATA_PATH = BASE_DIR / "examples" / "data" / "messy_medical_text.txt"
CLEAN_DATA_PATH = BASE_DIR / "examples" / "data" / "clean_medical_text.md"


def preview_text(title, path, max_length=600):
    text = path.read_text(encoding="utf-8")

    print(f"\n===== {title} =====")
    print(f"文件路径: {path}")
    print(f"字符数量: {len(text)}")
    print(text[:max_length])


preview_text("混乱数据集", MESSY_DATA_PATH)
preview_text("预处理后的结构化数据集", CLEAN_DATA_PATH)
```

示例输出：

```text
===== 混乱数据集 =====
文件路径: .../examples/data/messy_medical_text.txt
字符数量: 约 400
高血压患者要少吃盐多运动按时吃药如果头痛胸闷视物模糊要去医院...

===== 预处理后的结构化数据集 =====
文件路径: .../examples/data/clean_medical_text.md
字符数量: 约 1000
# 智能医疗机器人知识库

## 高血压日常管理
...
```

这个结果说明：

- 混乱文本缺少标题、段落和主题边界。
- 结构化 Markdown 文本有明确标题，更适合后续切分。
- 数据预处理本身不会生成 chunk，但会显著影响后续 chunk 的质量。
