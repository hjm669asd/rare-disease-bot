# 2.2 固定长度字符切分

固定长度字符切分是最容易理解的切分策略：按照固定字符数量把文本切成一段一段。

## 基本思想

例如设定：

```text
chunk_size = 100
chunk_overlap = 20
```

表示：

- 每个 chunk 目标长度约为 100 个字符。
- 相邻 chunk 之间重叠 20 个字符。

## 优点

- 简单直观。
- 实现成本低。
- 适合快速理解切分概念。
- 适合结构不明显的纯文本。

## 缺点

- 可能切断一句话。
- 可能切断一个完整医学建议。
- 不理解标题、段落、语义边界。
- 检索结果可能缺少完整上下文。

## 医疗场景中的问题

下面这句话如果被切断，风险很高：

```text
若出现明显头痛、胸闷、视物模糊或血压持续明显升高，应及时就医。
```

如果 chunk 只保留前半句，模型可能不知道“应及时就医”；如果只保留后半句，模型可能不知道触发条件是什么。

## 示例代码

下面的代码演示如何不用 LangChain，手写一个最基础的固定长度字符切分函数。

```python
def fixed_length_split(text, chunk_size, chunk_overlap):
    chunks = []
    start = 0

    while start < len(text):
        end = start + chunk_size
        chunk = text[start:end]
        chunks.append(chunk)
        start = end - chunk_overlap

    return chunks


text = "高血压患者应定期监测血压，减少钠盐摄入，保持规律运动，遵医嘱服药。"
chunks = fixed_length_split(text, chunk_size=30, chunk_overlap=8)

for index, chunk in enumerate(chunks, start=1):
    print(f"Chunk {index}: {chunk}")
```

示例输出：

```text
Chunk 1: 高血压患者应定期监测血压，减少钠盐摄入
Chunk 2: 少钠盐摄入，保持规律运动，遵医嘱服药。
```

这个结果说明：

- 固定长度切分只关心字符位置，不理解医学语义。
- `chunk_overlap=8` 让第二个 chunk 复用了第一个 chunk 结尾的一部分内容。
- 如果切分点刚好落在“风险条件”和“处理建议”中间，可能影响医疗问答质量。

## 适用场景

固定长度字符切分适合：

- 入门学习。
- 快速观察 chunk_size 的影响。
- 文档结构很弱、没有明显标题的文本。

不建议直接作为医疗 RAG 的最终方案。
