# 2.4 Markdown/标题结构切分

如果原始文档本身有清晰标题，例如 Markdown、技术文档、医疗指南目录，那么应该优先考虑按标题结构切分。

## 基本思想

标题结构切分会尽量保留章节层级，例如：

```markdown
# 高血压管理
## 饮食建议
## 运动建议
## 何时就医
```

切分后，每个 chunk 可以携带它所在的标题路径。

## 优点

- 保留文档结构。
- 检索结果更容易知道上下文来源。
- 适合指南、规范、课程文档、FAQ。
- 方便后续做引用和溯源。

## 缺点

- 依赖原始文档结构质量。
- 对没有标题的纯文本帮助不大。
- 如果标题设计很差，也会影响切分效果。

## 医疗场景示例

推荐整理成：

```markdown
# 高血压日常管理
## 血压监测
## 饮食控制
## 运动建议
## 用药提醒
## 危险信号
```

这样用户问“高血压什么时候要就医”时，更容易检索到“危险信号”小节。

## 示例代码

下面的代码演示如何按 Markdown 标题切分，并保留标题元数据。

```python
from langchain_text_splitters import MarkdownHeaderTextSplitter


markdown_text = """
# 高血压日常管理

## 饮食控制
建议减少钠盐摄入，少吃腌制食品。

## 危险信号
如出现明显头痛、胸闷、视物模糊，应及时就医。
"""

headers_to_split_on = [
    ("#", "一级标题"),
    ("##", "二级标题"),
]

splitter = MarkdownHeaderTextSplitter(headers_to_split_on=headers_to_split_on)
documents = splitter.split_text(markdown_text)

for document in documents:
    print(document.metadata)
    print(document.page_content)
```

示例输出：

```text
{'一级标题': '高血压日常管理', '二级标题': '饮食控制'}
建议减少钠盐摄入，少吃腌制食品。

{'一级标题': '高血压日常管理', '二级标题': '危险信号'}
如出现明显头痛、胸闷、视物模糊，应及时就医。
```

这个结果说明：

- 每个 chunk 不只包含正文，还携带标题路径 metadata。
- 用户询问“什么时候要就医”时，更容易定位到“危险信号”小节。
- 标题 metadata 后续可以用于答案引用、来源展示和检索过滤。

## 实战建议

如果你能控制知识库格式，推荐优先把数据整理为 Markdown 或类似结构化文本。

这也是为什么 2.1 强调：可以手动把混乱数据集改成格式清晰的数据集。
