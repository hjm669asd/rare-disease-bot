# 2.5 Token 切分

Token 切分是按照模型 tokenizer 的 token 数量来切分文本，而不是按照字符数量。

## 字符和 Token 的区别

字符是我们看到的文字单位，Token 是模型处理文本时使用的单位。

例如中文、英文、数字、标点在不同 tokenizer 中可能被切成不同 token。

## 为什么需要 Token 切分

大模型和 embedding 模型通常都有最大 token 限制。

如果只按字符估算长度，可能出现：

- 字符不多，但 token 很多。
- 混合中英文、数字、单位时估算不准。
- 文本超过模型限制导致报错或截断。

## 示例代码

下面的代码演示如何使用 LangChain 的 `TokenTextSplitter` 按 token 数量切分文本。

```python
from langchain_text_splitters import TokenTextSplitter


text = """
高血压患者应定期监测血压，减少钠盐摄入。
如果出现明显头痛、胸闷、视物模糊或血压持续明显升高，应及时就医。
HbA1c、LDL-C、140/90mmHg 等医学表达在 tokenizer 中可能被拆成不同 token。
"""

splitter = TokenTextSplitter(
    chunk_size=80,
    chunk_overlap=20,
)

chunks = splitter.split_text(text)

for index, chunk in enumerate(chunks, start=1):
    print(f"Chunk {index}: {chunk}")
```

示例输出：

```text
Chunk 1: 高血压患者应定期监测血压，减少钠盐摄入。
如果出现明显头痛、胸闷、视物模糊或血压持续明显升高，应及时就医。

Chunk 2: HbA1c、LDL-C、140/90mmHg 等医学表达在 tokenizer 中可能被拆成不同 token。
```

这个结果说明：

- Token 切分控制的是模型处理文本时的 token 数量，不是肉眼看到的字符数量。
- 中文、英文缩写、数字、单位混在一起时，token 数量可能和字符数量差异较大。
- 医疗场景中常见 `HbA1c`、`LDL-C`、`140/90mmHg` 等表达，因此生产环境更需要关注 token 长度。

注意：不同模型的 tokenizer 规则可能不同。生产环境中应尽量使用与目标模型兼容的 tokenizer。

## 优点

- 更贴近模型真实上下文限制。
- 适合生产系统控制输入长度。
- 对长文档更稳定。

## 缺点

- 初学理解成本更高。
- 依赖具体 tokenizer。
- 不同模型 token 规则不同。

## 医疗场景建议

医疗文本常有数字、单位、英文缩写，例如：

```text
HbA1c、LDL-C、140/90mmHg、eGFR
```

如果进入生产环境，建议使用 token 维度控制 chunk 长度，避免超出模型限制。

初级阶段可以先理解思想，中级阶段再深入不同 tokenizer 的差异。
