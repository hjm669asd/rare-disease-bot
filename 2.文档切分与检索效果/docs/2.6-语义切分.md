# 2.6 语义切分

语义切分的目标不是按固定长度切文本，而是尽量按照语义边界切分。

## 基本思想

语义切分会尝试判断哪些句子属于同一个主题，哪些句子之间发生了明显主题变化。

例如下面内容：

```text
高血压患者应减少钠盐摄入。建议保持规律运动。若出现胸闷或视物模糊，应及时就医。
糖尿病患者应控制总能量摄入。建议监测空腹血糖和餐后血糖。
```

理想情况下，语义切分应该把高血压内容和糖尿病内容分开。

## 常见实现方式

### 1. 基于 embedding 的语义断点

把句子转换成向量，计算相邻句子的语义相似度。

如果相邻句子相似度突然下降，就可能是主题切换点。

### 2. 基于大模型判断

让大模型判断哪些段落应该合并，哪些应该拆开。

这种方式效果可能更好，但成本更高、速度更慢，也更难稳定复现。

### 3. 规则 + 语义混合

先用标题、段落、标点粗切，再用 embedding 或模型做二次合并/拆分。

真实项目中更常见的是混合策略。

## 示例代码

下面是一个“简化版语义切分伪代码”，用于帮助理解基于 embedding 的语义断点思想。

```python
sentences = [
    "高血压患者应减少钠盐摄入。",
    "建议保持规律运动。",
    "若出现胸闷或视物模糊，应及时就医。",
    "糖尿病患者应控制总能量摄入。",
    "建议监测空腹血糖和餐后血糖。",
]

# 伪代码：真实项目中需要调用 embedding 模型。
sentence_embeddings = embed(sentences)

chunks = []
current_chunk = [sentences[0]]

for index in range(1, len(sentences)):
    similarity = cosine_similarity(
        sentence_embeddings[index - 1],
        sentence_embeddings[index],
    )

    if similarity < 0.6:
        chunks.append("".join(current_chunk))
        current_chunk = [sentences[index]]
    else:
        current_chunk.append(sentences[index])

chunks.append("".join(current_chunk))
```

假设相邻句子的相似度计算结果如下：

```text
句子1 和 句子2 相似度：0.82
句子2 和 句子3 相似度：0.74
句子3 和 句子4 相似度：0.31
句子4 和 句子5 相似度：0.79
```

示例输出：

```text
Chunk 1: 高血压患者应减少钠盐摄入。建议保持规律运动。若出现胸闷或视物模糊，应及时就医。
Chunk 2: 糖尿病患者应控制总能量摄入。建议监测空腹血糖和餐后血糖。
```

这个结果说明：

- 前三句都围绕高血压，所以被合并为同一个 chunk。
- 第四句开始切换到糖尿病，相似度明显下降，因此形成新的 chunk。
- 语义切分的目标是让一个 chunk 尽量只围绕一个医学主题。

这段代码重点表达思想：如果相邻句子的语义相似度明显下降，就可能说明主题发生了切换。

## 优点

- 更关注语义完整性。
- 适合主题混杂的文档。
- 有利于提升检索准确率。

## 缺点

- 实现复杂度更高。
- 依赖 embedding 模型质量。
- 成本和速度都比简单切分高。
- 初学阶段不一定容易调参。

## 医疗场景建议

医疗知识中，一个 chunk 最好只围绕一个问题或主题：

- 高血压饮食
- 高血压运动
- 高血压危险信号
- 糖尿病饮食
- 糖尿病血糖监测

如果一个 chunk 同时包含多个疾病主题，检索时可能把无关内容带给大模型。
