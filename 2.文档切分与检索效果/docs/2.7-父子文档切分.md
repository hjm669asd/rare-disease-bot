# 2.7 父子文档切分

父子文档切分是一种常见的 RAG 优化策略，也叫 Parent-Child Chunking。

## 要解决的问题

普通切分经常遇到一个矛盾：

- chunk 太小：检索精准，但上下文不足。
- chunk 太大：上下文完整，但检索不够精准。

父子文档切分试图同时获得两者优点。

## 基本思想

父文档负责提供完整上下文，子文档负责精准检索。

```text
原始文档
  ↓
切成较大的父 chunk
  ↓
每个父 chunk 再切成较小的子 chunk
  ↓
检索时匹配子 chunk
  ↓
返回时带回对应父 chunk
```

## 举例

父 chunk：

```text
【高血压日常管理】
高血压患者应定期监测血压，减少钠盐摄入，保持规律运动，遵医嘱服药。如果出现明显头痛、胸闷、视物模糊或血压持续明显升高，应及时就医。
```

子 chunk：

```text
减少钠盐摄入，少吃腌制食品、加工肉类和高盐零食。
```

用户问“高血压要少吃什么”，系统可以通过子 chunk 精准命中，再返回父 chunk 给模型，保证回答时有完整上下文。

## 示例代码

下面的代码演示父子文档切分的核心思想：父 chunk 保存完整上下文，子 chunk 用于精准检索。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter


text = """
【高血压日常管理】
高血压患者应定期监测血压，减少钠盐摄入，保持规律运动，遵医嘱服药。
如果出现明显头痛、胸闷、视物模糊或血压持续明显升高，应及时就医。
"""

parent_splitter = RecursiveCharacterTextSplitter(
    chunk_size=300,
    chunk_overlap=60,
    separators=["\n\n", "\n", "。", "，", " ", ""],
)

child_splitter = RecursiveCharacterTextSplitter(
    chunk_size=80,
    chunk_overlap=20,
    separators=["\n\n", "\n", "。", "，", " ", ""],
)

parent_chunks = parent_splitter.split_text(text)
child_to_parent = {}

for parent_id, parent_chunk in enumerate(parent_chunks):
    child_chunks = child_splitter.split_text(parent_chunk)

    for child_chunk in child_chunks:
        child_to_parent[child_chunk] = parent_id

print(child_to_parent)
```

示例输出：

```text
{
  "【高血压日常管理】\n高血压患者应定期监测血压，减少钠盐摄入，保持规律运动": 0,
  "减少钠盐摄入，保持规律运动，遵医嘱服药": 0,
  "如果出现明显头痛、胸闷、视物模糊或血压持续明显升高，应及时就医": 0
}
```

这个结果说明：

- 子 chunk 负责精准匹配用户问题。
- 字典中的 `0` 表示这些子 chunk 都来自第 0 个父 chunk。
- 检索时可以先命中较短的子 chunk，再返回对应父 chunk，给大模型提供更完整上下文。

真实项目中，通常会把子 chunk 存入向量库，把父 chunk 存入文档存储，并维护二者的映射关系。

## 优点

- 检索更精准。
- 回答上下文更完整。
- 适合长文档和复杂知识库。

## 缺点

- 实现复杂度更高。
- 需要维护父子 chunk 映射关系。
- 存储和检索逻辑比普通向量库复杂。

## 医疗场景建议

对于医疗指南、临床路径、长篇宣教材料，父子文档切分非常有价值。

初级阶段先理解思想；后续企业级 RAG 模块会实现更完整的父子检索结构。
