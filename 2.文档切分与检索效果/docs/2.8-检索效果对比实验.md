# 2.8 检索效果对比实验

学习切分策略不能只看理论，还要看检索结果。

本节目标是让你通过实验观察：不同切分参数和切分方式，会怎样影响 RAG 检索结果。

## 对比维度

### 1. chunk 数量

chunk_size 越小，chunk 数量通常越多。

### 2. chunk 完整性

观察一个医学建议是否被切断。

例如：

```text
如果出现明显头痛、胸闷、视物模糊或血压持续明显升高，应及时就医。
```

如果触发条件和处理建议被切到两个 chunk 中，回答质量可能下降。

### 3. 检索相关性

看用户问题能否检索到真正相关的 chunk。

例如：

```text
问题：高血压患者什么时候需要就医？
```

理想检索结果应该包含：

```text
明显头痛、胸闷、视物模糊、血压持续明显升高、及时就医
```

### 4. 噪声比例

检索结果中是否混入了无关疾病或无关主题。

比如问高血压，却检索到糖尿病、感冒、用药安全，这就是噪声。

## 实验建议

你可以依次测试：

```python
chunk_size=80
chunk_overlap=20
```

```python
chunk_size=180
chunk_overlap=40
```

```python
chunk_size=300
chunk_overlap=60
```

并观察：

- 哪种设置切得最碎？
- 哪种设置保留上下文最多？
- 哪种设置最容易检索到正确内容？
- 哪种设置会带来更多无关内容？

## 示例代码

下面的代码演示如何对同一个问题，使用不同 chunk 参数分别构建向量库并比较检索结果。

```python
from langchain_community.vectorstores import FAISS
from langchain_core.documents import Document
from langchain_dashscope import DashScopeEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter


def split_text(text, chunk_size, chunk_overlap):
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=chunk_overlap,
        separators=["\n\n", "\n", "。", "；", "，", " ", ""],
    )

    chunks = splitter.split_text(text)

    return [
        Document(
            page_content=chunk,
            metadata={"chunk_size": chunk_size, "chunk_overlap": chunk_overlap},
        )
        for chunk in chunks
    ]


text = "高血压患者应定期监测血压。若出现胸闷、视物模糊，应及时就医。"
question = "高血压患者什么时候需要及时就医？"
embeddings = DashScopeEmbeddings(model="text-embedding-v2")

for chunk_size, chunk_overlap in [(80, 20), (180, 40), (300, 60)]:
    documents = split_text(text, chunk_size, chunk_overlap)
    vectorstore = FAISS.from_documents(documents, embeddings)
    results = vectorstore.similarity_search(question, k=2)

    print(f"\nchunk_size={chunk_size}, chunk_overlap={chunk_overlap}")
    for result in results:
        print(result.metadata)
        print(result.page_content)
```

示例输出：

```text
chunk_size=80, chunk_overlap=20
{'chunk_size': 80, 'chunk_overlap': 20}
若出现胸闷、视物模糊，应及时就医。

chunk_size=180, chunk_overlap=40
{'chunk_size': 180, 'chunk_overlap': 40}
高血压患者应定期监测血压。若出现胸闷、视物模糊，应及时就医。

chunk_size=300, chunk_overlap=60
{'chunk_size': 300, 'chunk_overlap': 60}
高血压患者应定期监测血压。若出现胸闷、视物模糊，应及时就医。
```

这个结果说明：

- 小 chunk 可能更精准，但上下文更少。
- 中等 chunk 往往能同时保留问题条件和处理建议。
- 大 chunk 上下文更多，但真实长文档中也更容易混入无关内容。

## 本章结论

没有一种切分策略永远最好。

真实 RAG 项目通常需要：

```text
先清洗数据 → 选择初始切分策略 → 构建检索实验 → 根据结果调整参数
```

在医疗场景中，优先保证：

- 风险条件不要被切断。
- 处理建议不要脱离触发条件。
- 一个 chunk 尽量只围绕一个医学主题。
- 对资料不足的问题，模型不能强行生成诊疗建议。
