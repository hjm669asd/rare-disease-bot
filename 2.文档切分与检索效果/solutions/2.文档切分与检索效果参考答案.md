# 第二章参考答案：文档切分与检索效果

## 练习 1 参考

混乱数据集的问题包括：

- 没有标题。
- 没有段落边界。
- 多个疾病主题混在一起。
- 标点和结构不清晰。
- 不利于稳定切分。

结构化数据集更适合切分，因为它有明确的疾病主题、小节标题和段落边界。

如果处理 PDF OCR 文本，建议先清理：页眉、页脚、页码、乱码、重复行、广告、版权信息、无关导航、错误换行。

## 练习 2 参考

`chunk_size` 越小，chunk 数量通常越多，检索可能更精准，但上下文更少。

`chunk_size` 越大，chunk 数量通常越少，上下文更完整，但可能混入更多无关内容。

如果医学建议被切断，模型可能只看到条件或只看到处理建议，影响回答质量。

## 练习 3 参考

固定长度切分主要按字符数量硬切。

递归字符切分会优先按段落、换行、句号等自然边界切分，只有在内容过长时才继续细切。

`separators` 顺序很重要，因为它决定了优先保留哪种结构。中文文本需要加入 `。`、`，`，否则切分器不一定能按中文句子边界切开。

## 练习 4 参考

Markdown 标题切分会把标题层级保存到 metadata 中，例如：

```text
一级标题：智能医疗机器人知识库
二级标题：高血压日常管理
三级标题：危险信号
```

标题结构可以帮助系统知道 chunk 所属主题，方便检索、展示引用来源和后续过滤。

医疗 FAQ 可以按疾病、问题类型、风险等级设计标题，例如：

```markdown
# 高血压
## 日常管理
### 饮食建议
### 运动建议
### 危险信号
```

## 练习 5 参考

小 chunk 通常更聚焦，容易命中问题中的具体点，但可能上下文不足。

大 chunk 上下文更多，但可能带入无关信息，导致回答变得发散。

当前医疗知识库结构清晰，`chunk_size=180`、`chunk_overlap=40` 通常是比较平衡的入门参数。

如果问题是“糖尿病患者应该吃什么？”，理想检索结果应包含：

- 控制总能量摄入。
- 减少含糖饮料、甜点和精制碳水。
- 选择全谷物、蔬菜、优质蛋白和适量健康脂肪。
