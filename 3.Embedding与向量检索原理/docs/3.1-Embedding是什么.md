# 3.1 Embedding 是什么

Embedding 可以理解为：**把文本转换成一串数字向量**。

在 RAG 系统中，用户问题和知识库 chunk 都会先被转换成向量，然后才能做相似度检索。

## 为什么需要 Embedding

计算机不能直接理解中文句子的含义，但可以计算数字之间的距离。

例如：

```text
高血压患者要少吃盐
血压高的人应减少钠盐摄入
感冒患者应多休息
```

前两句话字面不同，但语义接近；第三句话主题不同。

Embedding 的目标就是让语义接近的文本在向量空间中距离更近。

## 在 RAG 中的位置

```text
原始文本 chunk
  ↓
Embedding 模型
  ↓
文本向量
  ↓
存入 FAISS 向量库
```

用户提问时：

```text
用户问题
  ↓
Embedding 模型
  ↓
问题向量
  ↓
与知识库向量做相似度比较
```

## 示例代码

```python
from langchain_dashscope import DashScopeEmbeddings


embeddings = DashScopeEmbeddings(model="text-embedding-v2")

texts = [
    "高血压患者要少吃盐。",
    "血压高的人应减少钠盐摄入。",
    "感冒患者应注意休息。",
]

vectors = embeddings.embed_documents(texts)

for text, vector in zip(texts, vectors):
    print(text)
    print(f"向量维度: {len(vector)}")
    print(f"前 5 个数字: {vector[:5]}")
```

示例输出：

```text
高血压患者要少吃盐。
向量维度: 1536
前 5 个数字: [0.012, -0.034, 0.056, ...]
```

这个结果说明：

- 一段中文文本会被转换成一个高维数字列表。
- 向量中的单个数字通常没有直观含义。
- 真正有意义的是向量整体在空间中的位置。
