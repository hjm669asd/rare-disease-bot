# 3.5 top_k 与检索结果数量

`top_k` 表示检索时返回多少条最相似的结果。

在 LangChain 中常见写法是：

```python
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
```

或者：

```python
results = vectorstore.similarity_search(question, k=3)
```

## k 太小的问题

如果 `k=1`，系统只返回最相似的 1 个 chunk。

优点：

- 噪声少。
- 上下文短。

缺点：

- 可能漏掉关键补充信息。
- 如果第一条检索错了，后续回答就容易错。

## k 太大的问题

如果 `k=8` 或更多，系统会返回很多 chunk。

优点：

- 召回更多信息。
- 不容易漏掉相关材料。

缺点：

- 容易混入无关内容。
- prompt 更长，成本更高。
- 大模型可能被噪声干扰。

## 示例代码

```python
question = "高血压患者什么时候需要及时就医？"

for k in [1, 2, 3]:
    results = vectorstore.similarity_search(question, k=k)
    print(f"k={k}, 返回结果数量: {len(results)}")

    for result in results:
        print(result.page_content)
```

示例输出：

```text
k=1, 返回结果数量: 1
如果出现明显头痛、胸闷、视物模糊，应及时就医。

k=2, 返回结果数量: 2
如果出现明显头痛、胸闷、视物模糊，应及时就医。
高血压患者应定期监测血压。

k=3, 返回结果数量: 3
如果出现明显头痛、胸闷、视物模糊，应及时就医。
高血压患者应定期监测血压。
糖尿病患者应监测血糖。
```

这个结果说明：

- `k` 越大，返回内容越多。
- 返回内容越多，不代表质量一定越好。
- 医疗 RAG 中要控制噪声，避免无关疾病信息进入回答上下文。
