# 第 3 章参考答案：Embedding 与向量检索原理

## 练习 1：解释 Embedding

Embedding 是把文本转换成数字向量的过程。

RAG 系统需要 Embedding，是因为向量库不能直接比较中文句子的语义，只能比较数字向量之间的距离或相似度。

在 RAG 中：

```text
知识库 chunk → embedding 向量
用户问题 → query 向量
```

然后系统比较 query 向量和 chunk 向量，找出最相关的内容。

## 练习 3：理解 FAISS 的职责

说法错误。

FAISS 不能像大模型一样生成医疗建议。

FAISS 的职责是：

```text
保存向量，并快速检索相似向量。
```

它不会生成自然语言答案，也不会理解医学知识。真正生成回答的是 LLM。

## 练习 4：调整 top_k

### k=1

优点：

- 返回内容少，噪声少。
- prompt 更短。

风险：

- 如果唯一结果不完整或不准确，模型会缺少依据。

### k=3

优点：

- 能召回更多相关上下文。
- 通常比 k=1 更稳妥。

风险：

- 可能混入少量不相关内容。

### k=8

优点：

- 召回范围更大，不容易漏信息。

风险：

- 容易混入无关疾病或无关建议。
- prompt 变长，成本升高。
- 医疗问答中可能造成回答混乱。

## 练习 5：理解相似度分数

第一条更适合作为回答依据：

```text
score: 0.32
高血压患者如出现胸闷、视物模糊，应及时就医。
```

原因：

- 它和问题主题一致，都是高血压及时就医。
- 它包含关键条件：胸闷、视物模糊。
- score 更小，通常表示距离更近。

第二条是感冒内容，与高血压问题不匹配，不适合作为主要依据。

## 练习 6：医疗检索可靠性

可以从以下维度判断：

- 是否命中正确疾病。
- 是否包含关键症状或触发条件。
- 是否包含处理建议。
- 是否混入无关疾病。
- 相似度分数是否足够好。
- 是否来自可信来源。
- 是否包含医疗安全提醒。

## 练习 7：修改代码实验

把 `k` 改成 `[1, 2, 4]` 后，通常会看到更多结果。

可能现象：

- `k=1` 返回最相关内容。
- `k=2` 增加一个补充上下文。
- `k=4` 可能把糖尿病或感冒内容也召回。

结论：

`k` 不是越大越好。医疗 RAG 要在“召回足够信息”和“减少无关噪声”之间取得平衡。
