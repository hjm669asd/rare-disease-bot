# 第 4 章参考答案：Retriever 检索器与 RAG 查询流程

## 练习 1：解释 Retriever

Retriever 是 RAG 系统中的检索器。

它负责接收用户问题，并从知识库中返回相关 `Document`。

可以理解为：

```text
用户问题 → Retriever → 相关文档
```

它本身不生成最终答案，而是为大模型提供回答依据。

## 练习 2：VectorStore 和 Retriever 的区别

第一段代码：

```python
results = vectorstore.similarity_search(question, k=3)
```

这是直接调用向量库的相似度搜索能力。

第二段代码：

```python
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
results = retriever.invoke(question)
```

这是先把向量库包装成 Retriever，再通过统一接口检索。

区别：

- `VectorStore` 更底层，直接负责向量存储和相似度搜索。
- `Retriever` 更适合接入完整 RAG 链路。
- 后续使用链式编排时，通常更推荐使用 Retriever。

## 练习 3：理解 k 参数

### k=1

优点：

- 返回内容少。
- 噪声低。
- prompt 更短。

风险：

- 可能漏掉关键补充信息。
- 如果第一条结果不准确，回答依据会很弱。

### k=3

优点：

- 可以召回更多上下文。
- 回答依据可能更完整。

风险：

- 可能混入无关内容。
- 医疗场景中可能把其他疾病的信息带入回答。

## 练习 4：构造 Prompt

示例答案：

```text
你是一个智能医疗科普助手。
请只根据下面资料回答问题。如果资料不足，请说明无法可靠回答。

资料：
高血压患者如果出现明显头痛、胸闷、视物模糊，应及时就医。

用户问题：
高血压患者什么时候需要及时就医？

请给出简洁回答，并说明本回答不能替代医生诊断。
```

## 练习 5：完整 RAG 流程排序

正确顺序：

```text
E. 文档切分并生成向量
D. 构建 FAISS 向量库
B. 用户提出问题
C. Retriever 检索相关文档
F. 拼接 context 并构造 prompt
A. 调用大模型生成回答
```

如果从系统初始化和查询两个阶段看，可以理解为：

```text
初始化阶段：E → D
查询阶段：B → C → F → A
```

## 练习 6：检索失败处理

系统不应该编造胃溃疡用药建议。

更安全的回答是：

```text
根据现有知识库资料，无法可靠回答胃溃疡用药问题。请咨询医生或补充相关医学资料。本系统内容仅用于健康科普，不能替代医生诊断。
```

原因：

- 当前知识库没有胃溃疡内容。
- 医疗用药问题风险较高。
- 基于无关资料回答可能误导用户。

## 练习 7：代码实验

运行 `4.2_retriever_k_compare.py` 后，一般可以观察到：

- `k=1` 返回最相关的一条结果。
- `k=2` 返回更多高血压相关上下文。
- `k=3` 可能开始包含糖尿病等不完全相关内容。

结论：

`k` 越大，召回越多，但噪声也可能增加。医疗 RAG 中需要谨慎设置。
