# 第 6 章参考答案：LCEL 链式编排与完整 RAG Chain

## 练习 1：解释 LCEL

LCEL 是 LangChain Expression Language。

它用于把 LangChain 组件编排成链式流程。

例如：

```python
chain = prompt | llm | StrOutputParser()
```

它解决的问题是：

- 让流程更清晰。
- 让组件组合更统一。
- 减少手动调用每一步的重复代码。
- 更适合构建完整 RAG Chain。

## 练习 2：理解管道符

```python
chain = prompt | llm | StrOutputParser()
```

执行顺序是：

```text
prompt 接收输入变量并生成 prompt
  ↓
llm 接收 prompt 并生成消息对象
  ↓
StrOutputParser 把消息对象转换成字符串
```

管道符 `|` 表示把左边组件的输出传给右边组件。

## 练习 3：RunnablePassthrough 的作用

`RunnablePassthrough()` 的作用是把用户原始问题原样传递下去。

在 RAG Chain 中：

```python
"context": retriever | format_docs
```

负责把问题用于检索资料。

```python
"question": RunnablePassthrough()
```

负责把同一个问题原样传给 Prompt 的 `{question}` 变量。

## 练习 4：补全 format_docs

答案：

```python
def format_docs(documents):
    return "\n\n".join(document.page_content for document in documents)
```

它的作用是把多个 `Document` 的正文内容拼接成一个字符串 context。

## 练习 5：解释最小 RAG Chain

### retriever | format_docs

先用 Retriever 根据用户问题检索相关文档，再把文档列表拼接成 context 字符串。

### RunnablePassthrough()

把用户问题原样传给 Prompt 的 `question` 字段。

### prompt

把 `context` 和 `question` 填入模板，生成大模型输入。

### llm | StrOutputParser()

先调用大模型生成回答，再把模型消息解析成普通字符串。

## 练习 6：来源信息

医疗 RAG 中建议把 `source` 放入 Prompt，因为：

- 可以让回答带来源引用。
- 方便开发者检查答案依据。
- 可以提升回答透明度。
- 有助于判断模型是否基于正确资料回答。
- 医疗场景中可追溯性非常重要。

## 练习 7：调试链路

如果最终答案不准确，可以优先检查：

- 用户问题是否正确传入。
- Retriever 检索到了哪些文档。
- 检索结果是否包含关键医学信息。
- `format_docs` 拼接后的 context 是否正确。
- 最终 prompt 是否包含清晰约束。
- 模型输出是否遵守结构和安全声明要求。

## 练习 8：代码实验

运行 `6.7_debug_lcel_chain.py` 后，应观察：

- 检索到的文档是否和问题相关。
- context 是否包含“胸闷”“视物模糊”“及时就医”等关键信息。
- prompt 是否明确要求只根据资料回答。
- 最终回答是否基于资料，并包含医疗安全声明。

结论：

调试 RAG Chain 时，不应该只看最终答案，而要逐层检查检索、context、prompt 和模型输出。
