# 7.8 检索评估与调参

检索优化不能只靠感觉，需要评估。

最简单的评估方式是准备一组测试问题和期望命中的文档。

## 为什么需要评估

不同参数会影响检索结果：

- `chunk_size`
- `chunk_overlap`
- `k`
- embedding 模型
- 是否 query rewrite
- 是否 rerank
- 是否 metadata filter

如果没有评估集，很难判断修改是否真的变好。

## 简单评估指标

### 1. 是否命中正确文档

用户问高血压危险信号，是否检索到了“高血压危险信号”文档。

### 2. 正确结果是否排在前面

正确结果在第 1 位比第 5 位更好。

### 3. 是否混入无关疾病

高血压问题中是否混入糖尿病或感冒。

## 示例代码

```python
eval_cases = [
    {
        "question": "高血压患者什么时候需要及时就医？",
        "expected_keyword": "及时就医",
    },
    {
        "question": "糖尿病患者要关注什么指标？",
        "expected_keyword": "HbA1c",
    },
]

retrieved_results = {
    "高血压患者什么时候需要及时就医？": "高血压患者出现胸闷、视物模糊，应及时就医。",
    "糖尿病患者要关注什么指标？": "糖尿病患者应关注糖化血红蛋白 HbA1c。",
}

for case in eval_cases:
    result = retrieved_results[case["question"]]
    hit = case["expected_keyword"] in result
    print(case["question"], hit)
```

示例输出：

```text
高血压患者什么时候需要及时就医？ True
糖尿病患者要关注什么指标？ True
```

这个结果说明：

- 可以用小型评估集快速检查检索效果。
- 每次调整参数后，都应该重新跑评估。
- 企业级 RAG 需要长期积累评估问题集。
