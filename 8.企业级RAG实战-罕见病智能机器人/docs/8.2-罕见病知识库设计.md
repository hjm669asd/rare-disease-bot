# 8.2 罕见病知识库设计

企业级 RAG 项目的第一步不是写接口，而是设计知识库。

对于罕见病智能机器人来说，知识库质量会直接影响检索结果和最终回答。

> 重要说明：本章中的罕见病资料只用于 RAG 技术教学和健康科普，不构成真实医疗建议、诊断或治疗方案。

## 为什么罕见病更需要 RAG

罕见病场景有几个特点：

- **疾病种类多**：不同疾病之间症状可能相似。
- **知识分散**：资料可能来自科普文章、诊疗指南、患者教育材料。
- **专业词多**：包含基因、遗传方式、临床表现、检查项目等术语。
- **误答风险高**：如果把疾病 A 的资料用于疾病 B，可能造成严重误导。

因此，罕见病 RAG 的知识库必须重视结构化和来源信息。

## 知识库应该包含什么

一个教学版罕见病知识库可以先包含以下字段：

```text
疾病名称
  ↓
基础介绍
  ↓
常见表现
  ↓
可能病因
  ↓
检查与诊断提示
  ↓
日常管理建议
  ↓
就医提醒
  ↓
资料来源
```

这些内容不要求覆盖真实医学全量知识，而是用于演示 RAG 如何检索和回答。

## 推荐 Markdown 结构

本章建议使用 Markdown 文件作为知识库。

示例结构：

```markdown
# 罕见病知识库

## 苯丙酮尿症

### 基础介绍
苯丙酮尿症是一种遗传代谢病。

### 常见表现
可能出现发育迟缓、特殊气味、皮肤和头发颜色较浅等。

### 日常管理
需要在医生指导下进行饮食管理和长期随访。

### 就医提醒
如果儿童出现发育异常，应及时到正规医疗机构就诊。

### 来源
教学示例资料
```

## 为什么要保留标题层级

标题层级有两个作用：

- **帮助切分**：切分文档时可以保留疾病名称和章节信息。
- **帮助引用**：回答时可以说明资料来自哪个疾病、哪个章节。

如果只把所有内容混成一大段，检索结果会更难解释。

## metadata 应该保存什么

在 LangChain 中，每个 `Document` 都可以带 `metadata`。

罕见病知识库建议保存：

- **source**：资料文件名。
- **disease**：疾病名称。
- **section**：章节名称。
- **doc_type**：资料类型，例如科普、管理建议、就医提醒。

这些 metadata 可以用于：

- 来源引用。
- 检索调试。
- 后续元数据过滤。
- 判断是否混入其他疾病资料。

## 知识库到 RAG 的流程

```text
Markdown 罕见病资料
  ↓
加载为 Document
  ↓
按标题或段落切分
  ↓
补充 disease、section 等 metadata
  ↓
Embedding 向量化
  ↓
写入 FAISS 向量库
  ↓
Retriever 根据用户问题检索
```

## 罕见病知识库的安全原则

设计医疗知识库时，需要遵守几个原则：

- **不写确定诊断**：机器人不能根据几句话判断用户患病。
- **不写个体化用药方案**：用药必须由医生决定。
- **保留就医建议**：涉及症状、诊断、治疗时提醒就医。
- **保留资料来源**：让回答可追溯。
- **资料不足时拒答**：不要让模型编造缺失内容。

## 本节小结

罕见病智能机器人不是先写模型调用，而是先设计好知识库。

一个适合教学的知识库至少要做到：

```text
结构清晰 + 便于切分 + 带来源 + 有安全边界
```
