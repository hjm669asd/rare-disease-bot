# 8.5 会话历史与多轮问答

真实机器人通常不是只回答一个问题。

用户可能会连续追问，例如：

```text
用户：什么是苯丙酮尿症？
机器人：……
用户：那日常饮食要注意什么？
```

第二个问题中的“那”依赖上一轮对话，这就需要会话历史。

## 什么是会话

会话可以理解为一次连续对话。

每个会话有一个 `session_id`：

```text
session_id = demo-user-001
```

同一个 `session_id` 下的问题和回答会被保存到同一段历史中。

## 为什么 RAG 需要会话历史

会话历史可以帮助系统理解上下文。

例如：

```text
第一轮：苯丙酮尿症是什么？
第二轮：它需要长期随访吗？
```

如果没有历史，第二轮中的“它”指代不清。

如果有历史，系统可以知道“它”大概率指的是苯丙酮尿症。

## 教学版会话存储

教学版可以用内存字典保存：

```text
session_id
  ↓
[
  用户问题 1,
  机器人回答 1,
  用户问题 2,
  机器人回答 2
]
```

这种方式简单直观，适合学习。

但它有明显限制：

- 服务重启后历史会丢失。
- 多进程部署时数据不共享。
- 不适合大量用户。

真实项目通常会使用 Redis 或数据库。

## 多轮问答和 RAG 的关系

多轮问答不是简单地把所有历史都塞进 Prompt。

如果历史过长，会造成：

- Prompt 太长。
- 成本变高。
- 模型注意力分散。
- 旧信息干扰新问题。

教学版可以只保留最近几轮对话。

```text
最近 3 轮历史
  +
当前问题
  +
检索到的知识库资料
  ↓
Prompt
```

## 推荐 Prompt 结构

```text
你是罕见病智能科普助手。

对话历史：
{history}

知识库资料：
{context}

用户当前问题：
{question}

要求：
1. 只根据知识库资料回答。
2. 如果资料不足，请说明无法根据现有资料可靠回答。
3. 不提供诊断结论或个体化治疗方案。
4. 结尾必须加入医疗安全声明。
```

## 会话历史不等于知识库

需要注意：用户说过的话不一定是事实。

例如用户说：

```text
我确定自己得了某种罕见病。
```

机器人不能直接把这句话当成诊断结论。

会话历史主要用于理解上下文，不应该替代可靠知识库。

## 多轮问答流程

```text
用户发送 question + session_id
  ↓
后端读取最近几轮历史
  ↓
Retriever 根据当前问题检索资料
  ↓
Prompt 同时包含 history、context、question
  ↓
LLM 生成回答
  ↓
保存本轮用户问题和机器人回答
  ↓
返回给前端
```

## 本节小结

会话历史让机器人更像真实应用，但也带来风险。

在医疗 RAG 中要记住：

```text
历史用于理解上下文
知识库用于提供依据
医生用于真实诊断
```
