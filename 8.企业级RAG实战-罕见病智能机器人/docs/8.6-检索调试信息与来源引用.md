# 8.6 检索调试信息与来源引用

企业级 RAG 项目不能只看最终回答。

尤其在医疗场景中，我们必须知道：

```text
机器人为什么这样回答？
它检索到了哪些资料？
这些资料是否真的支持答案？
```

这就需要检索调试信息和来源引用。

## 什么是来源引用

来源引用是指在回答中说明依据来自哪里。

例如：

```text
根据资料，苯丙酮尿症儿童需要在医生指导下进行饮食管理和长期随访。

来源：rare_disease_knowledge.md / 苯丙酮尿症 / 日常管理
```

来源引用可以帮助用户和开发者判断回答是否有依据。

## 什么是检索调试信息

检索调试信息是给开发者看的中间结果。

常见字段包括：

- **question**：用户问题。
- **top_k**：本次返回的检索数量。
- **retrieved_count**：实际检索到的文档数量。
- **documents**：检索到的文档片段。
- **metadata**：每个片段的来源、疾病、章节。

调试信息不一定全部展示给普通用户，但在学习和开发阶段非常重要。

## 为什么医疗 RAG 必须看检索结果

如果只看最终回答，很难发现问题。

例如用户问：

```text
苯丙酮尿症需要注意什么？
```

系统可能检索到：

```text
1. 苯丙酮尿症的饮食管理
2. 成骨不全症的骨折风险
3. 罕见病就医提醒
```

第 2 条可能是噪声。

如果不检查检索结果，模型可能把其他疾病内容混入回答。

## 来源引用的推荐结构

来源可以用列表返回给前端：

```json
[
  {
    "source": "rare_disease_knowledge.md",
    "disease": "苯丙酮尿症",
    "section": "日常管理"
  }
]
```

前端可以把它渲染成：

```text
参考来源：
- rare_disease_knowledge.md / 苯丙酮尿症 / 日常管理
```

## 调试信息的推荐结构

```json
{
  "top_k": 3,
  "retrieved_count": 3,
  "retrieved_documents": [
    {
      "content_preview": "苯丙酮尿症儿童需要在医生指导下进行饮食管理...",
      "metadata": {
        "disease": "苯丙酮尿症",
        "section": "日常管理"
      }
    }
  ]
}
```

`content_preview` 不需要返回全文，可以只返回前一小段，便于调试。

## 来源去重

多个 chunk 可能来自同一个章节。

如果不去重，前端会显示很多重复来源。

可以按下面字段去重：

```text
source + disease + section
```

去重后的来源更清晰。

## 检索调试流程

```text
用户问题
  ↓
Retriever 检索 top_k 个 Document
  ↓
提取 page_content 和 metadata
  ↓
生成 context 给 Prompt
  ↓
生成 sources 给前端
  ↓
生成 debug_info 给开发者
```

## 医疗场景中的检查重点

每次调试罕见病 RAG 时，可以重点看：

- 是否命中正确疾病。
- 是否混入其他疾病资料。
- 是否包含用户问题需要的章节。
- 是否包含就医提醒或安全声明。
- 来源是否可追溯。
- 资料是否足以支持回答。

## 本节小结

企业级 RAG 不应该是黑盒。

对于罕见病智能机器人来说，至少要返回：

```text
最终回答 + 来源引用 + 检索调试信息
```

这样才能更安全地发现问题、解释问题和优化问题。
