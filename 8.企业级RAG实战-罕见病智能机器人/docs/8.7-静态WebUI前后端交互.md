# 8.7 静态 WebUI 前后端交互

企业级 RAG 项目通常需要一个用户界面。

本章选择静态 WebUI，而不是 Vue 或 React，是为了减少初学者负担，把重点放在 RAG 服务化和前后端交互上。

## WebUI 负责什么

静态 WebUI 主要负责：

- 展示聊天界面。
- 接收用户输入。
- 调用后端 API。
- 展示机器人回答。
- 展示来源引用。
- 展示检索调试信息。

它不负责：

- 调用大模型。
- 保存 API Key。
- 构建向量库。
- 执行检索。

这些都应该由后端完成。

## 前后端交互流程

```text
用户在输入框提问
  ↓
点击发送按钮
  ↓
JavaScript 使用 fetch 请求 /api/chat
  ↓
FastAPI 后端执行 RAG
  ↓
返回 JSON
  ↓
JavaScript 渲染 answer、sources、debug_info
```

## fetch 请求示例

```javascript
const response = await fetch("http://127.0.0.1:8000/api/chat", {
  method: "POST",
  headers: {
    "Content-Type": "application/json"
  },
  body: JSON.stringify({
    session_id: "demo-session",
    question: question,
    debug: true
  })
});

const data = await response.json();
```

这段代码说明：

- 前端通过 HTTP 调用后端。
- 请求体是 JSON。
- 后端返回的也是 JSON。
- 前端再把 JSON 渲染到页面上。

## 页面区域设计

教学版 WebUI 可以分为四个区域：

```text
标题区
  ↓
聊天记录区
  ↓
输入区
  ↓
来源与调试信息区
```

### 1. 标题区

说明机器人身份：

```text
罕见病智能机器人
仅用于健康科普和 RAG 技术教学
```

### 2. 聊天记录区

展示用户问题和机器人回答。

### 3. 输入区

包含：

- 输入框。
- 发送按钮。
- 清空按钮。

### 4. 来源与调试信息区

展示：

- 检索到的来源。
- 命中的疾病和章节。
- 调试片段预览。

## 为什么前端不能保存 API Key

API Key 属于敏感信息。

如果写在前端 JavaScript 中，用户可以直接在浏览器里看到。

正确做法是：

```text
API Key 存在后端 .env
  ↓
前端只调用后端接口
  ↓
后端再调用模型服务
```

这也是前后端分离项目的重要安全边界。

## 跨域问题

如果前端页面和后端服务不在同一个地址，浏览器可能会遇到跨域限制。

例如：

```text
前端：http://127.0.0.1:5500
后端：http://127.0.0.1:8000
```

这时后端需要允许前端访问。

FastAPI 中通常可以使用 CORS 中间件解决。

## 错误提示设计

前端不应该只显示“失败”。

更好的提示包括：

- 后端服务是否启动。
- 网络请求是否失败。
- API 是否返回错误信息。
- 用户问题是否为空。

例如：

```text
请求失败，请确认 FastAPI 后端服务已启动。
```

## 本节小结

静态 WebUI 的重点不是复杂页面效果，而是理解：

```text
前端收集问题
后端执行 RAG
前端展示回答和来源
```

掌握这条链路后，就可以进一步升级到 Vue、React 或企业内部系统。
